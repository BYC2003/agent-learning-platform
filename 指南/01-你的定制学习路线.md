## 一、结论先行

你不需要走「从零装环境 → 学语法 → 学框架」的通用路线。你的最优路径是：

**跳过环境搭建 → 用 1 周补 Python 工程短板 → 直接进入 8 个实战项目 → 用项目反哺知识 → 4-5 个月形成可投递的作品集。**

原因很简单：这个岗位考的不是「你会不会 Python 语法」，而是「你能不能把 Agent 做成能上线、有效果、成本可控的产品」。项目产出就是最好的学习方式，也是唯一能写进简历的东西。

### 1 周内必须补掉的三个 Python 短板

1. **类型注解与 pydantic**：写函数时标注类型，用 pydantic 做数据校验。Agent 项目的输入输出全靠它。
2. **pytest 写测试**：至少会给自己的函数写 3 个测试用例。没有测试就没有 CI，没有 CI 就不算工程能力。
3. **async / await**：知道 `asyncio.gather` 能并发请求，知道超时怎么设。LLM 应用几乎全是异步的。

## 五、复刻开源项目的六步法

1. **看**：先读 README 与目录结构，搞清它解决什么问题、需要什么前置条件（20 分钟）。
2. **跑**：单独建 `-ref` 参考目录 clone，独立虚拟环境，把官方最简示例原样跑通（1 小时）。
3. **验**：改一个小参数或换一句话，确认你知道每一行在做什么（30 分钟）。
4. **拆**：读懂核心文件的主流程，用三句话写下它的工作方式（2 小时）。
5. **搬**：新建自己的项目，把最小可用部分搬进去，绝不直接改参考仓库（1 小时）。
6. **改**：换成你的场景，加日志、错误处理、评测与 README（半天到两天）。

三条铁律：

- 参考目录永远用 `-ref` 结尾，永不修改，方便对照上游更新。
- 跑通官方示例只算入门，能换场景并给出量化指标才算掌握。
- 每复刻一个项目，写一篇 500 字笔记：它解决什么问题、核心抽象是什么、我踩了什么坑。
